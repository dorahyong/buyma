## 1. 구조 — 왜 한번 얼면 안 풀리는가

```
① raw_scraped_data   몰 원본
② ace_product_variants   소싱 최신 옵션 목록      ← 여기가 진실이어야 함
③ source_offering_options  merge 재료
④ listing_options    출품 옵션                     → BUYMA
```

| 사실 | 확인 방법 |
|---|---|
| 옵션 목록을 새로 만드는 건 **변환뿐** | `DELETE ace_product_variants` 후 재삽입이 변환 2개에만 존재 |
| 변환은 **미등록 상품만** 처리 | `raw_to_ace_converter.py:780` (주석: "등록된 건 stock 전담") |
| 수집도 **등록 상품은 건너뜀** | `--skip-existing` = `get_published_product_ids()` 제외 |
| 재고동기화는 **있는 줄의 상태만** 고침 | 12개 전부 `INSERT INTO ace_product_variants` **0건** (전수 확인) |
| ③④는 몰이 아니라 ②를 베낌 | `reconcile_runner` 에 HTTP 호출 0개 (순수 DB→DB) |
| ③에 쓰는 코드는 **INSERT 하나뿐** | 저장소 전체에 UPDATE·DELETE 없음 (전수 확인) |

**→ 바이마에 올라가는 순간 옵션 목록은 동결. 그 뒤로는 재고 표시만 켜졌다 꺼졌다 합니다.**

**중요:** 못 고치는 이유는 데이터가 없어서가 **아닙니다.**
재고동기화는 매 회차 몰에 접속해 최신 목록을 통째로 받아옵니다. 받아온 걸 안 쓸 뿐입니다.
